# System-wide actor integrity follow-up — 2026-11-14

The wider review found additional instances of the same failure pattern: a historical fact was reconstructed from mutable current data, lost while moving between API/UI representations, or not recorded atomically. The fixes below extend the earlier [audit](data-integrity-audit-2026-11-13.md) and [operations rules](historical-actor-integrity.md). They apply to former, inactive, archived and replacement Dean, Secretary, Director, Program Head and VPAA accounts. Configured President signatures remain document evidence, not a separate authenticated approval stage.

## Priority and implementation ledger

P1 means false attribution, execution outside current authority, or loss of provenance. P2 means incomplete retained evidence or misleading presentation. These describe the risk before remediation, not confirmed malicious changes.

| ID / priority | Affected modules and records | Root cause and potential impact | Safeguard implemented |
| --- | --- | --- | --- |
| F-01 / P1 | `ReportsController::roomSummary`; `room_requests`, `users`; department reports | Requester names came from the current user relationship. Renaming or archiving the requester changed or removed historical attribution. | Read the request's recorded actor snapshot. Missing legacy names display `Actor unavailable`; a successor is never substituted. |
| F-02 / P1 | `DepartmentScheduleController` revision/snapshot descriptions; `schedule_history_items`, `faculties` | Missing instructor labels were rebuilt through current faculty descriptors. An old revision could acquire a later name. | Use original before/after names or snapshot metadata for instructor identity. Missing identity is explicitly unavailable, with provenance indicated. Current non-person master labels can still enrich the view. |
| F-03 / P1 | `TeachingHistoryArchive`, faculty teaching-history endpoints; history versions/items | Instructor/course filters ran before choosing the latest semester/department archive. When a later archive replaced instructor A with B, A's older assignment could reappear as the effective archived assignment. | Select the latest archive for each semester/department first, then filter its contents. Earlier versions remain intact in history. |
| F-04 / P1 | `ProgramController`, `DepartmentsController`, `DesignationController`, `CoursesController`; corresponding master tables and authentication audit | Soft archival and its audit event were separate writes. A logging failure could commit archival without its provenance. | Enclose both operations in one transaction. Failure rolls back archival; retry records one original actor event. Faculty, rooms, users and semester archive paths already had transaction protection. |
| F-05 / P1 | `GenerateYearLevelSchedulePreview`, `ScheduleAuthorizationService`; generation runs, users, programs, sections | Execution checked account activity/department but did not recheck generation capability and exact program ownership after queue delay. A transferred or demoted requester could still execute previously queued work. | Recheck current capability and writable programs at execution; cancel unauthorized runs. The original request actor stays recorded. Historical snapshots never grant current permissions. |
| F-06 / P1 | Scheduler `initialDataMapper`, `useScheduler`, `InstructorTeachingLoadButton`; schedule response mapping and individual print | Mapping discarded inline signatures or creator evidence. Same-ID mutation responses omitting unchanged evidence could erase it locally. Draft print logic also selected today's preparer officeholder and a fixed role title. | Retain inline signatures, creator ID and creator identity. Preserve existing evidence when a mutation omits it, while respecting explicit null. Draft preparers use the recorded creator/capacity; historical blocks remain authoritative. Current eligible reviewers may appear only in unsigned draft slots. |
| F-07 / P2 | `ScheduleGenerationRun`, `RoomRecoveryCase`, `CurriculumImport`, `CurriculumImportService`; three origin tables | Generation/recovery retained only mutable user references. Import confirmations retained original name/ID/time but lacked the complete actor context and database immutability; import parent cascades could erase confirmation evidence. | Capture prospective actor snapshots with role, department, program and active state. Native guards freeze origin IDs and snapshots, including legacy nulls. Import record JSON and confirmation are immutable; deletion is rejected and parent FKs restrict updates/deletes. Ordinary progress and insertion-time summary completion remain allowed. |
| F-08 / P2 | `VpaaDashboardPage`, `AdministrativeActivityPanel`, Activity Log, History preview and archive dialogs | Dashboard mapping dropped actor type, missing actors could be labeled `System`, and nullable names/usernames produced misleading labels. | Preserve actor type and distinguish unknown actors from explicitly recorded system actions. Render missing identities without fabricated names or `null` username labels. |
| F-09 / P2 | `dataCache`; persisted scheduler/report data | A corrected API response did not invalidate existing persisted data, allowing old identity displays to survive for the cache lifetime. | Bump cache format to v6 and invalidate v5 persisted entries. |
| F-10 / P2 | `CurriculumImportPage`, Reports page explanatory text | A missing import confirmer was labeled `you`, attributing the confirmation to the current reader. Report copy described signatures as current institutional settings. | Missing confirmer displays `Actor unavailable`; report copy describes the recorded approval signatures. |
| F-11 / P1 | `RoomRequestModals`, room-request API contract; `room_requests.actor_snapshots.decisions` | The screen paired the retained original approver/time with the latest review remarks. After A approved and B revoked, B's remarks could appear to belong to A. | Render every recorded decision with its own actor, time and remarks. Missing decision actors stay unavailable. Legacy revoke/cancel remarks without decision evidence are explicitly unattributed. |

Shared safeguards use the existing `ActorIdentity` and `PreservesApprovalActors` mechanisms. The latter now preserves a legacy null snapshot during unrelated workflow updates instead of manufacturing an empty snapshot object. No new approval stage, replacement-account reassignment, or historical backfill was introduced.

## Remaining work, in order

1. **P1 — Independent evidence retention and legacy reconciliation.** Retain backups/ledgers outside runtime-writable storage. Investigate the 88 suspect versions and missing former-account identities against contemporaneous evidence. Any supported correction must append a separately attributed record; never overwrite the original.
2. **P1 — Other environments.** Deploy the backend, frontend, six migrations and runtime credential separation together, after backup and restored-copy verification. Complete original-column comparisons before leaving maintenance.
3. **P2 — Operational origin retention policy.** Generation runs and recovery cases have immutable origin IDs/snapshots, but remain deletable operational records; generation-run department/semester FKs still cascade on hard deletion. No application deletion path was found. These tables must not be described as permanently append-only approval/audit history. If their complete operational evidence must also be permanent, add explicit retention/parent restrictions and a size/retention policy before introducing any cleanup endpoint. Import confirmations already have permanent delete/parent protection.
4. **P2 — Dormant recommendations.** `schedule_recommendations` still has requested/accepted/rejected actor fields without event-time snapshots. No application reader/writer or active workflow was found. Account FKs already restrict destructive account operations, but enabling this feature requires the same snapshot and completed-decision protections. Do not treat the unused schema as an implemented approval workflow.
5. **P2 — Partial live/archive teaching-history policy.** Faculty teaching history excludes a whole semester's archive when any live row for that faculty exists. This can omit otherwise archived assignments during a partial live reconstruction. Define the intended merge policy, then cover mixed live/archive semesters. This review changed latest-archive selection without silently changing that policy.
6. **P2 — Non-actor historical metadata.** `ApprovedScheduleHistory` can enrich missing legacy split fields from today's `ScheduleSplit`; some historical timetable details can therefore drift. Live teaching/report views intentionally use current faculty profiles under stable IDs. Decide which outputs are current views versus historical documents before adding further snapshot requirements.
7. **P3 — Scale and stronger tamper evidence.** Normalize/index historical feeds as volume grows while preserving complete filters. Consider independent immutable retention or externally verifiable digests for protection against privileged database administrators.

The review covered application models/relationships, migrations/FKs/triggers, controllers/services, queued work, archive operations, history/report/export consumers and frontend actor/signature mappings. No further active approval-actor overwrite path was identified within that coverage; this is a bounded source/data review, not proof that privileged administrators or uninspected external systems cannot alter evidence.
